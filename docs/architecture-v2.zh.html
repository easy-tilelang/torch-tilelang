Dynamo 入口与双后端
安装后即可使用 torch.compile(backend="tilelang")，也可通过 make_backend(GraphConfig(...)) 配置。默认组合为 AscendC + TVM-FFI，指定 target="pto" 可选择 PTO 代码生成与执行。
入口注册后端配对适配器测试
FX 转 Relax 与 TIR
fx_to_relax 将纯计算分区导入 Relax，用 LegalizeOps 生成 call_tir。例如 relu(x + bias) * bias 在关闭融合时对应三次内核调用。
图转换最小示例内核计数测试
分区与回退
默认 conservative 策略提取支持的子图，遇到无法安全重排的副作用可整图交给 Torch。分区构建或数值校验失败时，默认可回退。开启 strict=True 后会报告这些错误。设备执行错误直接向上传播。
分区实现边界测试
有序分区与执行报告
partition_policy="ordered" 只合并相邻的可编译节点，外部调用与原生写入保留原顺序。Dynamo 后端返回的 runner.graph_report 记录原生节点及原因、各分区的内核数、编译执行次数和回退次数。严格模式也允许计划内的原生节点。
有序分区共享缓存测试
张量、输出与执行流
TorchGraphRunner 用 Torch 分配内核输出，在当前 NPU stream 上执行，记录外部输入的使用流，并在中间值最后一次使用后释放引用。支持嵌套元组返回和跨调用保留历史输出。

有限支持

已有执行路径，取决于输入、算子参数和调度规则

推理输入与布局
同一 NPU 上的 FP16、BF16、FP32 张量可进入分区。各维须为正静态整数，数据连续且存储偏移为零。整数、量化张量和任意跨步视图超出当前输入范围。
输入校验输入用例
逐元素、广播与转换
覆盖四则运算、部分一元函数和浮点类型转换。可证明访存对齐时可生成四路向量访存，否则使用标量路径。各个函数接受的参数见算子清单。
算子转换逐元素调度调度测试
归约、Softmax 与 RMSNorm
在完整末轴上调度归约。Softmax 由前端展开，RMSNorm 示例用已支持的算子构建归一化计算。其他轴与超长行缺少通用调度。
归约规则SoftmaxRMSNorm
矩阵乘与后处理
二维 GEMM 要求两个输入同为 FP16 或同为 BF16，且 M、N、K 均为 16 的倍数。已有 bias + ReLU 后处理示例。批量矩阵乘、FP32 输入及非对齐尺寸缺少对应调度。

训练与反向传播
后端只编译推理分区。梯度模式开启时，输入校验会拒绝 requires_grad=True 的张量。仓库尚无生成反向图或梯度内核的路径。
梯度校验推理约束测试
符号动态形状内核
分区依赖具体尺寸，运行器会检查形状、类型和布局。输入签名变化可以触发重新准备分区，单个内核尚不能接受符号维度和任意运行时尺寸。
符号维度检查签名与重编译
原位写入与别名算子的原生内核
缓存写入、修改输入的算子及返回别名的操作可由 Torch 在原位置执行。当前 TileLang 分区没有为这类操作生成内核的通用路径。
原生边界存储别名测试
动态 Relax 分支与标量内核参数
执行器支持静态 call_tir、张量、元组及顺序绑定。relax.If、MatchCast 绑定和直接传入内核的标量参数超出当前执行计划的表达范围。
IR 与内核参数检查
CPU 和 CUDA 原生图后端
当前目标解析只接受 Ascend 的代码生成与执行组合。CPU 可以运行图转换和注入的测试内核。通过这个 Dynamo 入口选择 CUDA 会报错。

支持哪些算子？

下表列出可编译的常见 PyTorch 调用。输入须为同一 NPU 上连续、零存储偏移的静态推理张量。除矩阵乘另有要求外，输入类型为 FP16、BF16 或 FP32。同名函数的参数和 ATen 重载也会影响分区。如何维护这份清单？

四则运算与广播
add、sub / subtract、mul / multiply、div / divide / true_divide，以及 + - * /。支持张量广播和实数常量。加减要求 alpha=1，除法使用 rounding_mode=None。
算术转换标量数值测试
一元逐元素
relu（含非原位 nn.ReLU）、exp、sqrt、rsqrt、square。pow(x, 2) 或 x ** 2 展开为 x * x，只接受常量指数 2。
逐元素调度一元函数测试
浮点类型转换
x.float()、x.half()、x.bfloat16()、x.to(dtype)、x.type_as(y)。支持三种浮点类型之间的转换，设备和布局须保持一致。在有序分区中，同类型转换和独立的纯转换片段留给 Torch，以保留别名行为。
类型转换有序分区限制
末轴归约与 Softmax
sum、mean、amax 支持保留或移除归约轴。softmax 及 nn.Softmax(dim=-1) 展开成求最大值、减法、指数、求和与除法。均要求完整末轴，长度最多 16384。amax 只返回值，带索引的 max(dim) 尚无对应入口。
归约规则Softmax 示例
二维矩阵乘
mm、matmul、@。两个矩阵须同为 FP16 或同为 BF16，M、N、K 都须为 16 的倍数，乘加用 FP32 累加。匹配的 GEMM + bias + ReLU 模式有融合后处理用例。
GEMM 调度融合图测试

新增一个算子要改哪些代码？

算子列表怎么维护？

开发者在 backend.py 维护 FX 准入列表，决定哪些调用可以尝试编译。本页的算子支持表记录通过验证的用法和限制。例如 pow 已登记，当前可编译的是常量指数 2。沿用已有 Python 列表即可，另建 JSON 或 YAML 会多出一份需要同步的名称清单。查看 FX 准入列表

变更类型维护位置
新增函数将函数名加入 _FUNCTION_NAMES。_METHOD_NAMES 已包含这个集合，有同名张量方法时，一起核对两种调用的参数。
新增仅限 Tensor 的方法将方法名加入 _METHOD_NAMES 的额外集合，例如已有的 half 和 type_as。
新增直接调用的模块将具体的 nn.Module 类型加入 _MODULE_TYPES，并检查前端转换和有序分区对该模块的处理。
扩展已有算子的范围沿用原有名称，按需调整参数、分区或调度规则。例如扩展 sum 的归约轴时，修改轴判断和访存规则。

每次新增支持，在同一次变更中更新实现、支持与拒绝用例，以及本页对应条目的参数、类型或形状范围。

实现与验证步骤

先用一个最小模型在 Dynamo 后端回调里查看 gm.graph，确定需要支持的 FX 调用形式、参数和输入类型。再用 fx_to_relax 查看生成的 PrimFunc，由实际 TIR 决定能否复用现有调度。

  1. 限定可编译的调用。 在 _SupportedOperators.is_node_supported 检查支持的参数。若算子有专属的重载、轴、别名或模块规则，再同步 ordered.py 的 _native_reason，让超出范围的调用保留在 Torch。分区器 · 有序分区
  2. 表达 PyTorch 数值语义。 frontend.py 的 _AscendFXImporter.create_convert_map 继承 TVM 的 FX 转换。已有映射且 dtype、舍入和参数语义匹配时可直接复用。需要特殊处理时，在此添加转换或分解。例如 _square_power 将 pow(x, 2) 转成已有的 relax.multiply。转换映射与平方分解
  3. 只扩展现有规则无法生成的内核。 新逐元素数学指令先核对 elementwise.py 的 _SCALAR_INTRINSICS、_validate_scalar 和低精度计算规则，可对照 exp / sqrt / rsqrt。如果目标代码生成器尚不能发出该指令，可分解成已有运算，或在 TileLang 中补对应目标的实现。新归约方式或 GEMM 后处理看 operators.py 的 try_schedule_reduction、try_schedule_gemm。引入全新调度族时才在 schedule_primfunc 登记。沿用现有 call_tir 张量接口即可复用运行时。逐元素 · 归约与 GEMM · 调度分派
  4. 证明新算子确实进入了编译分区。 补 FX 转换、支持参数和拒绝边界用例。对新调度检查 AscendC 与 PTO 生成的源码。真机用包含新算子的最小图与 eager 对齐，检查目标适配器、内核数和回退次数。混合图使用有序分区时，还要在 graph_report.partitions 的 targets 中找到新算子，避免把同图其他内核的成功误计为该算子覆盖。前端与分区测试 · 逐元素测试 · 归约与 GEMM 测试 · 真机图测试

例：把 sum 扩展到非末轴。 FX 已能识别 sum，前端也已把 dim 传给 Relax。改动集中在 try_schedule_reduction 的归约轴与访存规则，以及 _native_reason 对新支持轴的检查。可从现有的非末轴拒绝用例出发，为新增范围补正例，再保留其他越界情况的拒绝测试。归约边界测试
