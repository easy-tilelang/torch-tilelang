从 PyTorch 图
到 Ascend 内核

torch-tilelang 是 PyTorch 的推理编译后端。它从计算图中取出可编译的分区，借助 TileLang 生成内核，在昇腾 NPU 上执行。

查看编译流程 跟读代码示例

项目全景

Dynamo 提供 FX 图，TileLang 编译内核。连接两者的图执行器用 Torch 分配中间张量和输出。

编译流程

沿着一张 FX 图，看 PyTorch 的张量运算如何变成 Ascend NPU 上的内核调用。

从 FX 图划出可编译的分区

Dynamo 把捕获的图交给 tilelang_backend。后端检查原地修改、别名和前向钩子，再把受支持的算子组合成分区。像 torch.sin 这样的纯算子可以留给 PyTorch，与编译分区一起执行。每个分区在第一次收到真实张量时编译。

分区是什么意思？

把计算图中的算子分组，交给不同的执行方式处理。 例如加法、ReLU 和乘法可交给 TileLang，暂不支持的 sin 留在 Torch：

[add → relu] → sin → [mul]
 分区 1        Torch   分区 2
 TileLang              TileLang

分区之间传递 Torch Tensor。一个分区可以包含多个 kernel；本文的 add → relu → mul 是一个分区，默认未融合时仍启动三个内核。

输入
FX GraphModule、样例输入和后端选项
输出
含 _CompiledPartition 子模块的可调用图

含副作用、输入含非张量或全图没有可编译分区时，默认交回 PyTorch 执行。开启 strict=True 会在这些情形下报错。

对应源码backend.py · make_backend

把分区转换成 Relax 与 TIR

fx_to_relax 根据张量形状与类型翻译运算。Relax 描述数据怎样流动。合法化步骤把运算展开成可调度的 TIR 函数，由 relax.call_tir 引用。

输入
一个 FX 分区及其真实 NPU 张量
输出
包含 Relax 主函数和未调度 PrimFunc 的 IRModule

分区要求同一 NPU 上的连续推理张量，每维为正的静态整数，存储偏移为零，支持 float16、bfloat16、float32。默认配置下，输入校验或转换失败会回退到该分区的 PyTorch 实现。

对应源码frontend.py · fx_to_relax

为每个内核选择 Ascend 调度

build_runner 收集主函数引用的 PrimFunc。调度器依次尝试逐元素、归约和矩阵乘规则。匹配成功后，兼容层把调度结果交给 tilelang.compile。运行时再把调用顺序整理成执行计划。

输入
未调度的 PrimFunc 和目标配置
输出
持有已编译内核及执行计划的基线 runner

AscendC 使用 tvm_ffi 执行适配器，PTO 使用 pto 适配器。分区内核缺少适用调度时，默认回退到 PyTorch。严格模式会抛出错误。

对应源码schedule.py · schedule_primfunccompat/tilelang.py · compile_kernel

先与 eager 对验，再决定是否融合

后端用相同输入运行基线与原始分区，对比输出。默认 fusion="off"，通过校验即可使用基线。设为 "profile" 时，还会另行编译融合候选并比较正确性、设备耗时与整段执行耗时。

输入
基线 runner、原始分区和同一组输入
输出
经过验证的基线，或实测通过的融合 runner

基线结果不符时，默认使用 eager。融合候选未通过校验或性能门槛时，保留基线。设备执行错误会向上传递。

对应源码fusion.py · validate_runner / select_fusion

按计划执行，把张量交还给 Torch

TorchGraphRunner 在 Torch 当前 NPU 流上依次启动内核，由 Torch 为输出分配空间，并在中间值最后一次使用后释放对应的引用。

输入
已选 runner 和本次调用的张量
输出
由 Torch 持有的结果张量或张量元组

每个分区保留最近一次签名及其 runner。形状、类型、设备、步幅、存储偏移、梯度状态等相同时直接复用，签名变化时重新准备。

后端入口 · backend.py

  • config.py用 GraphConfig 读取编译选项。
  • frontend.py用 fx_to_relax 转换可编译分区。
  • runtime.py用 build_runner 创建分区执行器。
  • fusion.py用 validate_runner 对照 PyTorch 校验分区结果。

图执行器 · runtime.py

  • schedule.py用 schedule_primfunc 为每个 PrimFunc 选择调度。
  • compat/tilelang.py用 compile_kernel 编译调度后的函数。
  • fusion.py用 kernel_count 统计内核调用，并分析归约输出。

调度分派 · schedule.py

  • elementwise.py首先尝试逐元素调度。
  • operators.py随后尝试末轴归约和二维 GEMM。

数值校验与融合 · fusion.py

  • compat/profiler.py比较基线与融合候选的设备耗时和端到端耗时。
  • errors.py捕获 MeasurementUnavailableError，保留基线。

设备计时 · compat/profiler.py

  • errors.py用 MeasurementUnavailableError 表示无法取得计时样本。

示例走读

跟着仓库中的广播加法、ReLU 和乘法，观察一个分区如何执行三个算子。

test_torch_compile.py
def model(x, bias):
    return torch.relu(x + bias) * bias

compiled = torch.compile(
    model, backend="tilelang",
    fullgraph=True, options={"strict": True},
)
torch.testing.assert_close(compiled(x, bias), model(x, bias))

一次调用里发生了什么？

x [7, 65]bias [65]

bias 广播到 7 行。三个相邻算子都受支持，Dynamo 交付的 FX 图可划成一个 TileLang 分区。

在此例的默认未融合路径中，分区包含三个 call_tir。执行器依次启动三个内核，得到形状为 [7, 65] 的输出，再由测试与 PyTorch eager 结果对照。
