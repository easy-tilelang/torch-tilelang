从 PyTorch 到 Ascend NPU

torch-tilelang 将 PyTorch 推理图中受支持的分区编译为 TileLang 内核，在昇腾 NPU 上执行。

编译流程

跟踪一个 FX 分区从捕获、编译到再次执行的路径。

  1. 预检并分区

    Dynamo 交出 FX 图。后端检查目标与代码生成器，将支持的算子组合成分区。

  2. 转换 FX 分区

    分区首次收到真实张量时检查输入。FX 转为 Relax，算子计算经 LegalizeOps 降为 TIR。

  3. 调度并编译

    依次尝试逐元素、归约和 GEMM 调度，交给 TileLang 编译，按调用顺序构建基础执行计划。

  4. 校验基础计划

    用同一组输入运行基础计划和原 PyTorch 分区，核对输出结构、类型及数值。

默认路径保存基础执行器及输入签名，然后调用执行器。
启用融合fusion="profile" 会编译融合候选。候选通过校验且实测耗时达标时采用融合计划，否则保留基础计划。

  1. 再次进入同一分区

    分区读取梯度模式与输入的形状、类型、设备、步幅、存储偏移和 requires_grad。

  2. 命中最近签名

    张量的值可以变化。签名一致时，分区直接取出上次保存的执行器。

  3. 运行既有计划

    编译路径由 Torch 分配内核输出，在当前 NPU 流上启动内核。已回退的分区则继续调用原 PyTorch 实现。

签名变化分区按新输入重新准备执行器，并替换此前保存的签名和执行器。

失败发生在哪一步？

  • 目标预检失败

    目标与适配器冲突或缺少代码生成器时，分区前直接抛错。

  • 整图无法分区

    遇到不安全副作用、非张量输入或没有支持的分区时，默认由 PyTorch 执行整图。strict=True 时抛错。

  • 分区准备失败

    输入检查、转换、基线编译失败，或基线输出校验未通过，默认仅此分区回退。strict=True 时抛错。

  • 融合候选被拒绝

    候选编译失败、数值不符或缺少合格的计时结果时，保留已通过校验的基础执行器。

  • 设备执行失败

    内核运行或同步产生的错误直接传给调用方。

执行报告查看 graph_report.fallback_reason 定位整图回退，或在 graph_report.partitions 中查看各分区的回退原因与调用计数。

运行一个推理分区

下面的模型将一个长度为 65 的偏置广播到 7 行，然后依次执行 ReLU 和乘法。

Python · torch.compile
import torch

def model(x, bias):
    return torch.relu(x + bias) * bias

compiled = torch.compile(
    model, backend="tilelang", fullgraph=True,
    options={"target": "ascendc", "strict": True},
)
x = torch.randn(7, 65, device="npu")
bias = torch.randn(65, device="npu")
with torch.no_grad():
    torch.testing.assert_close(compiled(x, bias), model(x, bias))

哪些输入可以编译？

输入须位于同一张 NPU，采用正的静态维度、连续布局和零存储偏移。不同算子还有各自的调度条件。

逐元素
支持 fp16、bf16、fp32，可处理受支持的广播和类型转换。
末轴归约
对完整末轴求和、均值或最大值，长度上限为 16,384。
二维 GEMM
两个输入均为 fp16 或均为 bf16，M、N、K 都是 16 的倍数。
